모듈 06 · 가설검정과 p-값

p-값을 손으로 만들어보기

p-값을 공식으로 배우면 평생 헷갈립니다. 대신 라벨을 섞어보면 됩니다. "A와 B가 사실 아무 차이 없었다면, 우연만으로 이만큼 벌어질 수 있었을까?" — 이 질문에 직접 답을 만들어봅시다.

1. 섞기 실험 — p-값이 만들어지는 과정

A안과 B안을 비교했더니 B가 4점 높게 나왔다고 합시다. 여기서 물어야 할 질문은 하나입니다.

"A와 B가 사실 똑같았다면, 순전히 운으로 4점 차이가 날 수 있었을까?"

이 질문에 답하는 가장 정직한 방법은 실제로 해보는 것입니다. A와 B가 똑같다면 어떤 사람이 A그룹이고 어떤 사람이 B그룹인지는 아무 의미가 없습니다. 그러니 라벨을 떼서 섞어버려도 결과가 크게 달라지면 안 됩니다.

  1. 모든 데이터를 한 통에 붓고 A/B 라벨을 뗍니다.
  2. 무작위로 다시 절반씩 A와 B로 나눕니다. (1번 섞기 버튼)
  3. 두 그룹의 평균 차이를 기록합니다. — 이건 순전히 우연으로 생긴 차이입니다.
  4. 이걸 수백 번 반복합니다. (500번 섞기)

그러면 ②번 히스토그램이 만들어집니다. 이게 바로 "아무 효과도 없는 세상에서 차이가 어떻게 흩어지는가"입니다. 통계학에서는 이걸 귀무분포라고 부릅니다.

마지막으로, 실제 관측된 차이(파란 세로선)를 그 위에 얹습니다. 그 선보다 바깥쪽에 있는 빨간 영역의 비율이 p-값입니다. 끝입니다. 공식도, 표도, 정규분포도 필요 없었습니다.

2. p-값의 정확한 정의

정의 · p-값
p  =  P( 관측된 것만큼 또는 그 이상으로 극단적인 결과 | 귀무가설이 참 )
  • 귀무가설
    H₀    "차이가 없다" — 우리가 반박하려고 세워두는 기본 입장. 위 실험에서 라벨을 섞는 행위가 곧 H₀를 사실로 만드는 것입니다
  • |"~라는 조건 하에서". 이 방향이 핵심입니다 — 아래 오해 상자 참고
  • 극단적양측검정이면 |차이|가 더 큰 것, 단측이면 한쪽 방향으로만 더 큰 것
  • α유의수준. p < α면 "귀무가설을 기각"합니다. 관례적으로 0.05지만 법칙이 아니라 관습입니다
✗ 오해 — 조건이 뒤집혔습니다 "p = 0.03이면 귀무가설이 참일 확률이 3%다."
→ p는 H₀가 참일 때 이런 데이터가 나올 확률이지, 이런 데이터가 나왔을 때 H₀가 참일 확률이 아닙니다. "비가 오면 땅이 젖을 확률"과 "땅이 젖었으면 비가 왔을 확률"이 다른 것과 같습니다.
✓ 사실 "차이가 정말 없었다면, 이 정도 차이가 우연히 나올 일은 100번 중 3번뿐이다."
→ 그래서 "차이가 없다"는 가정이 의심스러워지는 겁니다. 증명한 게 아니라 의심할 근거를 얻은 것입니다.
p-값이 답하지 않는 질문들
  • 효과가 얼마나 큰가? → 신뢰구간과 효과크기가 답합니다(모듈 05).
  • 이 결과가 재현될 확률은? → p값은 재현성과 직접 관계가 없습니다.
  • 대립가설이 참일 확률은? → 빈도주의 p값은 이 질문에 답하지 않습니다.
  • 실무적으로 의미 있는가? → §5 참고. 이게 제일 중요한데 p값은 침묵합니다.

3. 직접 해보는 4가지 실험

실험 A · 효과가 진짜 0일 때 (p값의 정체 확인) "진짜 효과 크기"를 0으로 놓고, 새 실험 데이터 → 500번 섞기를 열 번쯤 반복해보세요.
  • p값이 0.9, 0.3, 0.6, 0.02… 제멋대로 나옵니다. H₀가 참이면 p값은 0~1 사이 균등분포입니다.
  • 스무 번쯤 하면 한 번쯤 p < 0.05가 나옵니다. 효과가 전혀 없는데도 말이죠. 이게 1종 오류이고, α=0.05는 곧 "20번에 1번은 이렇게 속겠다"는 선언입니다.
실험 B · 효과는 그대로, n만 키우기 (통계적 유의성의 함정) 효과를 1(아주 작게)로 고정하고 n을 10 → 50 → 300으로 올리며 각각 500번 섞어보세요.
  • 같은 크기의 효과인데 n이 커질수록 p값이 작아집니다.
  • ②번 히스토그램이 점점 좁아지기 때문입니다(σ/√n, 모듈 04). 좁아진 분포에서는 같은 차이도 훨씬 "극단적"으로 보입니다.
  • 결론: n만 충분히 크면 아무리 하찮은 차이도 "통계적으로 유의"해집니다. p값이 작다는 건 "효과가 크다"가 아니라 "0은 아닌 것 같다"는 뜻일 뿐입니다.
실험 C · 잡음을 키우기 (왜 실험 설계가 중요한가) 효과는 5로 두고 σ를 5 → 30으로 올려보세요. 개인차가 크면 같은 효과도 우연에 묻혀 안 보입니다. 실무에서 σ를 줄이는 것(측정 정밀화, 대상 동질화, 짝지은 설계)이 n을 늘리는 것만큼 강력한 이유입니다.
실험 D · 섞기 횟수의 의미 500번만 섞으면 p값은 1/500 = 0.002 단위로만 나옵니다. "p < 0.002"보다 정밀한 값이 필요하면 더 섞어야 합니다(자동 버튼). 실무에서 순열검정은 보통 10,000회를 씁니다.

4. 1종 오류 · 2종 오류 · 검정력

가설검정은 결국 둘 중 하나로 틀릴 수 있는 판정입니다. 법정 비유가 정확합니다 — 피고인은 무죄로 추정되고(H₀), 유죄를 입증할 책임은 검사에게 있습니다.

진실: 효과 없음 (H₀ 참)진실: 효과 있음 (H₀ 거짓)
기각함
"효과 있다"		 1종 오류 (α)
무고한 사람 유죄
없는 효과를 발표 → 재현 실패		 정답 ✓
검정력 = 1 − β
기각 못함
"모르겠다"		 정답 ✓ 2종 오류 (β)
진범을 놓침
효과가 있는데 못 찾음 → 기회 손실
검정력 (Power)
검정력  =  1 − β  =  P( 효과가 진짜 있을 때, 그걸 잡아낼 확률 )
보통 0.8 이상을 목표로 설계합니다
  • ↑ n검정력이 올라갑니다 — 가장 흔한 해결책
  • ↑ 효과크기잡기 쉬워집니다 (내가 못 정하는 경우가 많음)
  • ↓ σ측정 정밀화·설계 개선. 종종 n 늘리기보다 싸게 먹힙니다
  • ↑ α기준을 느슨하게 — 대신 1종 오류가 늘어납니다. 맞바꿈입니다
검정력이 낮은 연구는 "효과 없음"을 증명하지 못합니다 n이 작아서 p > 0.05가 나온 걸 "효과가 없다"고 보고하는 건 흔한 오류입니다. 어두워서 안 보이는 것과 거기 없는 것은 다릅니다. (모듈 05 §5의 3번·4번 구분과 같은 이야기입니다.) 게다가 검정력이 낮으면, 운 좋게 유의하게 나온 결과는 효과크기가 과장돼 있습니다.

5. 통계적 유의성 ≠ 실무적 중요성

실험 B에서 봤듯 n이 크면 아무 차이나 유의해집니다. 그래서 p값 옆에는 항상 효과크기가 있어야 합니다.

효과크기 · Cohen's d
d  =  x̄B − x̄As합동
  • d차이를 표준편차 단위로 환산 — n에 영향받지 않습니다
  • 0.2 / 0.5 / 0.8관례적으로 작음 / 중간 / 큼. 분야마다 기준이 다르니 절대시하지 말 것
보고할 때는 세 가지를 함께
  • 효과크기 — 얼마나 큰가 (실무 단위로: "전환율 +2.3%p", "체류 +41초")
  • 신뢰구간 — 얼마나 확실한가 (모듈 05)
  • p값 — 우연으로 설명 가능한가

가장 중요한 건 실험 전에 "이 정도는 나와야 도입할 가치가 있다"는 최소 유의미 효과(MDE)를 정해두는 것입니다. 그게 없으면 p값은 아무것도 결정해주지 못합니다.

6. p-해킹과 다중검정

실험 A에서 봤듯, 효과가 없어도 20번에 1번은 p < 0.05가 나옵니다. 그러면 20번 시도하면 되겠네가 됩니다. 이게 p-해킹입니다. 대부분은 악의가 아니라 자기도 모르게 일어납니다.

실무에서 실제로 벌어지는 p-해킹
  • 지표 쇼핑. 전환율이 안 나오면 체류시간, 그것도 안 되면 재방문율… 지표 10개를 보면 하나쯤은 유의해집니다.
  • 세그먼트 쪼개기. "전체는 아니지만 20대 여성 안드로이드 사용자에서는 유의했다." 쪼갤수록 검정 횟수가 늘어납니다.
  • 몰래 훔쳐보기(peeking). 매일 대시보드를 보다가 유의해진 날 실험을 멈추기. 이것만으로 실제 1종 오류율이 20~30%까지 올라갑니다.
  • 사후 가설 세우기(HARKing). 결과를 본 뒤 "원래 이걸 예상했다"고 쓰기.
  • 이상치 제거 기준을 결과 보고 정하기.
방어하는 방법
  • 사전 등록. 주요 지표 1개, 표본 크기, 중단 규칙, 이상치 기준을 데이터를 보기 전에 문서로 남깁니다. 가장 효과적인 방어입니다.
  • 다중검정 보정. k개를 검정하면 기준을 낮춥니다. Bonferroni: α/k (보수적), 지표가 많으면 FDR (Benjamini–Hochberg).
  • 탐색과 확증을 분리. 탐색에서 찾은 건 가설이지 결론이 아닙니다. 새 데이터로 다시 검증하세요.
  • 중간에 보려면 순차검정(O'Brien–Fleming 등) 설계를 쓰세요. 그냥 보면 안 됩니다.

7. 실무 체크리스트

단계확인할 것
설계 전주요 지표 1개 확정 · MDE 결정 · 검정력 0.8 기준 표본 수 계산 · 실험 기간 고정
실행 중중간에 결과 보지 않기 · 무작위 배정이 실제로 되었는지 확인(A/A 테스트)
분석관측 단위 독립성 확인 · 효과크기와 신뢰구간 먼저 · p값은 마지막
보고"+2.3%p (95% CI 1.2~3.4, p=0.003, n=8400)" 형식 · 검정한 지표 전부 공개
한 줄 요약 · p-값은 "우연만으로 이만큼 나올 수 있었나"에 대한 답입니다. 그 이상도 이하도 아닙니다. 얼마나 큰지는 효과크기가, 얼마나 확실한지는 신뢰구간이 답합니다.

이 모듈 요약

  • 라벨을 섞어 만든 분포 = 귀무분포. 관측값보다 극단적인 비율 = p-값.
  • p는 P(데이터 | H₀)이지 P(H₀ | 데이터)가 아니다. 조건을 뒤집지 말 것.
  • H₀가 참이면 p값은 균등분포. α=0.05는 "20번에 1번 속겠다"는 선언.
  • n이 크면 아무 차이나 유의해진다. 유의성과 중요성은 별개.
  • 1종 오류(α, 헛것을 봄) ↔ 2종 오류(β, 못 봄). 검정력 = 1−β ≥ 0.8로 설계.
  • 여러 번 검정하면 보정이 필수. 최선의 방어는 사전 등록.
  • 보고는 항상 효과크기 + 신뢰구간 + p값 세트로.
