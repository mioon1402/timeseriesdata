행렬 연산과 역행렬

행렬 곱은 "행과 열을 곱해서 더한다"로 계산합니다. 계산은 그게 맞습니다. 하지만 의미를 이해하려면 관점이 하나로는 부족합니다. 이 강의에서는 같은 곱셈을 네 가지로 읽는 법을 익히고, 역행렬이 "변환을 되돌리는 것"이라는 걸 눈으로 확인합니다.

0. 기초 다지기 — 크기가 맞아야 곱할 수 있다

행렬의 크기는 (행 개수) × (열 개수) 로 씁니다. 3 × 2 행렬은 가로줄 3개, 세로줄 2개죠. 행이 먼저입니다. 헷갈리면 "행렬"이라는 말 자체가 행-열 순서라고 기억하세요.

곱셈이 가능한 조건
A (m × n)  ×  B (n × p)  =  C (m × p)
  • 가운데A의 열 수와 B의 행 수가 같아야 합니다. 다르면 곱할 수 없습니다
  • 바깥결과의 크기는 바깥쪽 두 숫자가 됩니다
왜 하필 이 조건인가
2강에서 Ax 는 A의 열들을 x 만큼 섞는 것이라고 했습니다. 섞으려면 가중치 개수(x의 성분 수)와 재료 개수(A의 열 수)가 같아야겠죠. 곱셈 조건은 그 당연한 요구를 적어놓은 것뿐입니다.
행렬 곱은 순서를 바꾸면 안 됩니다 숫자는 3 × 5 = 5 × 3 이지만 행렬은 일반적으로 AB ≠ BA 입니다. 크기가 안 맞아 아예 계산이 안 되는 경우도 많고, 크기가 맞아도 값이 다릅니다. 아래 실습에서 직접 확인합니다.

1. 전치 (Transpose)

전치는 행과 열을 맞바꾸는 연산입니다. AT 로 씁니다. 대각선을 거울 삼아 뒤집는다고 생각하면 됩니다.

전치
A = 123 456  ⟹  AT = 14 25 36
  • 크기2×3 이 3×2 가 됩니다
  • (AB)T= BTAT — 순서가 뒤집힙니다. 자주 틀리는 곳입니다
  • (A+B)T= AT + BT — 덧셈은 순서가 그대로
전치는 왜 이렇게 자주 나오나
  • 내적을 uTv 로 적기 위해 (8강)
  • ATA 는 항상 정사각·대칭이 됩니다 — 최소제곱법(10강)과 SVD(16강)의 핵심 도구
  • 딥러닝에서 차원을 맞추려고 끝없이 등장합니다

2. 행렬 곱을 보는 네 가지 관점

아래 C = BC 를 예로, 완전히 같은 계산을 네 가지로 읽어봅니다. 결과는 당연히 전부 같습니다. 다른 건 무엇을 보느냐입니다.

예제
B = 2013 ,  C = 1425  ⟹  BC = 28719
관점읽는 법언제 쓰나
① 원소별
내적		 결과의 (i, j) 칸 = B의 i번째 행 · C의 j번째 열의 내적 손으로 계산할 때. 가장 기본
② 열 관점 결과의 각 열 = B × (C의 그 열) = B의 열들의 선형결합 의미를 이해할 때. 2강의 연장
③ 행 관점 결과의 각 행 = (B의 그 행) × C = C의 행들의 선형결합 소거법(3강)을 행렬로 볼 때
④ 외적 합 (B의 k번째 열) × (C의 k번째 행) 을 모두 더한 것 SVD·저랭크 근사(16·17강). 데이터를 층으로 쌓는 시각
데이터 공학에서 중요한 건 ②와 ④ · ②는 "이 행렬이 무엇을 섞고 있는가"를 알려주고, ④는 "이 행렬을 단순한 조각 몇 개의 합으로 쪼갤 수 있는가"를 알려줍니다. ④가 바로 이미지 압축과 추천 시스템의 원리입니다(17·18강).

3. 행렬은 변환이다

이제 행렬을 공간을 주무르는 기계로 봅시다. 아래에서 행렬의 네 값을 바꿔보세요. 회색 격자가 원래 공간이고, 파란 격자가 A 를 통과한 뒤의 모습입니다.

e₁ = (1,0) 이 가는 곳–
e₂ = (0,1) 이 가는 곳–
행렬식 det–
역행렬–
행렬의 열 = 기저벡터가 가는 곳 · 슬라이더를 보면 알 수 있듯이, A의 첫 번째 열이 곧 e₁=(1,0)의 도착지이고 두 번째 열이 e₂=(0,1)의 도착지입니다. 행렬을 만들고 싶으면 "기저벡터를 어디로 보낼지"만 정하면 됩니다. (19강에서 본격적으로)
[특이행렬] 버튼을 눌러보세요 격자가 직선으로 납작하게 눌립니다. 2차원이 1차원으로 찌그러진 거죠. 이렇게 되면 되돌릴 수 없습니다 — 서로 다른 점들이 같은 자리로 뭉개졌으니 어디서 왔는지 알 방법이 없습니다. 그래서 역행렬이 존재하지 않습니다. det = 0 은 "납작해졌다"는 신호입니다(12강).

4. 역행렬 — 되돌리는 변환

숫자에서 3 × ⅓ = 1 이듯, 행렬에서도 곱하면 아무것도 안 한 것과 같아지는 짝이 있습니다. 그 "아무것도 안 함"이 단위행렬 I 입니다.

역행렬의 정의
A A−1 = I   그리고   A−1 A = I
I = 1001   (대각선만 1, 나머지 0)
  • I단위행렬. Ix = x — 어떤 벡터에 곱해도 그대로 둡니다
  • 가역역행렬이 있는 행렬. Invertible / Nonsingular
  • 특이역행렬이 없는 행렬. Singular. det = 0

위 그림에서 [역변환도 함께 보기]를 켜보세요. 주황 격자가 A−1 의 변환입니다. 두 변환을 연달아 적용하면 원래 격자로 정확히 돌아옵니다.

2×2 역행렬 공식
A = abcd  ⟹  A−1 = 1ad − bc d−b−ca
  • ad − bc행렬식. 이게 0이면 0으로 나누게 되어 역행렬이 없습니다
  • 주의이 간단한 공식은 2×2 에서만 통합니다. 3×3 이상은 §5의 방법을 씁니다
곱의 역행렬은 순서가 뒤집힙니다
(AB)−1 = B−1 A−1

양말과 신발로 기억하세요. 양말 → 신발 순으로 신었다면, 벗을 때는 신발 → 양말 순입니다. 마지막에 한 것을 먼저 되돌리죠. 전치 (AB)T = BTAT 도 같은 모양입니다.

5. 가우스-조던으로 역행렬 구하기

3강에서 [A | b] 를 붙여 소거했듯이, 이번엔 [A | I] 를 붙여 소거합니다. 대각선 위쪽까지 전부 0으로 만들고 피봇을 1로 나누면, 왼쪽이 I 가 되고 — 오른쪽에 A−1 이 남습니다.

가우스-조던
[ A | I ]   — 소거 →   [ I | A−1 ]
  • 왜 되나왼쪽 A 를 I 로 만든 연산들의 총합이 곧 A−1입니다. 그 연산을 오른쪽 I 에도 똑같이 가했으니 A−1I = A−1 이 남죠

6. numpy 실습

import numpy as np np.set_printoptions(precision=3, suppress=True) A = np.array([[1, 2, 3], [4, 5, 6]]) print("A 크기 :", A.shape, " ← (행, 열)") print("A.T 크기 :", A.T.shape) print("\nA.T =") print(A.T)
B = np.array([[2, 0], [1, 3]]) C = np.array([[1, 4], [2, 5]]) print("B @ C =") print(B @ C) print() print("① 원소별 (0,0) 칸 :", B[0, :] @ C[:, 0]) print("② 열 관점 첫 열 :", C[0, 0] * B[:, 0] + C[1, 0] * B[:, 1]) print("③ 행 관점 첫 행 :", B[0, 0] * C[0, :] + B[0, 1] * C[1, :]) 외적합 = sum(np.outer(B[:, k], C[k, :]) for k in range(2)) print("④ 외적 합 =") print(외적합) print(" B@C 와 같은가:", np.array_equal(외적합, B @ C))
print("B @ C =\n", B @ C) print("\nC @ B =\n", C @ B) print("\n같은가:", np.array_equal(B @ C, C @ B)) print() print("(BC)ᵀ == CᵀBᵀ :", np.array_equal((B @ C).T, C.T @ B.T)) print("(BC)ᵀ == BᵀCᵀ :", np.array_equal((B @ C).T, B.T @ C.T), " ← 이건 틀린 식")
* 와 @ 는 완전히 다릅니다 numpy 에서 B * C 는 같은 자리끼리 곱하기(원소별)이고, B @ C 가 행렬 곱입니다. 크기가 같으면 둘 다 에러 없이 돌아가서 조용히 틀린 답이 나옵니다. 가장 흔한 버그 중 하나입니다.
print("B * C (원소별) =") print(B * C) print("\nB @ C (행렬곱) =") print(B @ C)
B_inv = np.linalg.inv(B) print("B⁻¹ =") print(B_inv) print("\nB @ B⁻¹ =") print(B @ B_inv) print("\n단위행렬인가:", np.allclose(B @ B_inv, np.eye(2))) print() print("(BC)⁻¹ == C⁻¹B⁻¹ :", np.allclose(np.linalg.inv(B @ C), np.linalg.inv(C) @ np.linalg.inv(B)))
# [B | I] 를 만들어 소거한다 M = np.hstack([B.astype(float), np.eye(2)]) print("[B | I] =") print(M) M[0] /= M[0, 0] # 1행 피봇을 1로 M[1] -= M[1, 0] * M[0] # 2행에서 x 소거 M[1] /= M[1, 1] # 2행 피봇을 1로 M[0] -= M[0, 1] * M[1] # 1행에서 y 소거 (위쪽까지) print("\n소거 후 =") print(M) print("\n오른쪽 절반이 B⁻¹ 인가:", np.allclose(M[:, 2:], B_inv))
특이 = np.array([[1., 2.], [2., 4.]]) # 2행 = 1행의 2배 print("det =", np.linalg.det(특이)) try: np.linalg.inv(특이) except np.linalg.LinAlgError as e: print("역행렬 없음:", e) print("→ 이 변환은 평면을 직선으로 눌러버려 되돌릴 수 없다")

7. 실무: 역행렬을 구하지 마세요

Ax = b 를 풀 때 x = A−1b 라고 배웠으니 역행렬을 구해서 곱하고 싶어집니다. 하지만 실무에서는 그렇게 하지 않습니다.

import time rng = np.random.default_rng(0) n = 400 큰A = rng.random((n, n)) + n * np.eye(n) b = rng.random(n) t = time.perf_counter(); x1 = np.linalg.solve(큰A, b); t1 = time.perf_counter() - t t = time.perf_counter(); x2 = np.linalg.inv(큰A) @ b; t2 = time.perf_counter() - t print(f"solve : {t1*1000:6.1f} ms 최대오차 {np.abs(큰A @ x1 - b).max():.2e}") print(f"inv @ b : {t2*1000:6.1f} ms 최대오차 {np.abs(큰A @ x2 - b).max():.2e}") print() print("→ solve 가 더 빠르고 더 정확합니다.") print(" (정확한 배수는 실행 환경에 따라 달라집니다)")
왜 solve 를 써야 하나
  • 계산량 — 역행렬을 만드는 건 Ax=b 를 n번 푸는 것과 같습니다. 우리는 한 번만 풀면 되는데요.
  • 정확도 — 나눗셈이 더 많이 일어나 반올림 오차가 쌓입니다. 위 실습에서 오차 자릿수를 비교해 보세요.
  • 희소성 파괴 — 0이 잔뜩인 큰 행렬(추천 시스템 등)의 역행렬은 0이 거의 없는 빽빽한 행렬이 됩니다. 메모리가 터집니다.
규칙: 코드에 inv(A) @ b 가 보이면 solve(A, b) 로 바꾸세요. A−1 은 이론을 적기 위한 기호이지 계산 절차가 아닙니다.

4강 요약

  • 곱셈은 A의 열 수 = B의 행 수 여야 가능하고, 결과 크기는 바깥 두 숫자입니다.
  • AB ≠ BA. 전치와 역행렬은 곱에서 순서가 뒤집힙니다(양말-신발).
  • 행렬 곱을 보는 네 관점 — 의미는 ②열 관점, 분해는 ④외적 합으로 봅니다.
  • A의 열 = 기저벡터가 가는 곳. 행렬을 만들려면 그것만 정하면 됩니다.
  • 역행렬은 변환을 되돌리는 것. 공간이 납작해지면(det=0) 되돌릴 수 없습니다.
  • [A|I] → [I|A⁻¹] 가 역행렬을 구하는 체계적 방법입니다.
  • 실무에서는 inv 대신 solve. 더 빠르고 더 정확합니다.
