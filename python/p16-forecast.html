예측해보기

드디어 미래를 예측합니다. 그런데 이 강의의 진짜 주제는 예측이 아니라 검증입니다. "잘 맞는 것처럼 보이게" 만드는 건 쉽고, 정직하게 재는 것이 어렵거든요. 그리고 놀랍게도 — 가장 단순한 방법이 이깁니다.

이 강의에서 배우는 것
  1. 학습/검증 분리 — 시간 순서를 지켜서
  2. 평가 지표 — MAE, RMSE, MAPE
  3. 기준선부터 만들기 (가장 중요)
  4. 지수평활과 SARIMA
  5. 결과 — 단순한 게 이겼습니다
  6. 예측구간 — 점이 아니라 범위로
  7. 실무 체크리스트

1. 학습/검증 분리

예측 모델을 평가하려면 모델이 본 적 없는 데이터가 필요합니다. 그런데 시계열에서는 반드시 시간 순서대로 잘라야 합니다.

import pandas as pd df = pd.read_csv("cafe_sales.csv", parse_dates=["date"]) s = df.set_index("date").asfreq("D")["sales"].interpolate() H = 28 # 예측 기간: 4주 학습, 검증 = s[:-H], s[-H:] print(f"학습 {len(학습):3d}일 {학습.index[0].date()} ~ {학습.index[-1].date()}") print(f"검증 {len(검증):3d}일 {검증.index[0].date()} ~ {검증.index[-1].date()}")
무작위 분리는 시계열에서 반칙입니다

일반 머신러닝에서 쓰는 train_test_split(shuffle=True) 를 시계열에 쓰면 미래로 과거를 예측하게 됩니다.

12월 15일 데이터로 학습해서 12월 3일을 맞히는 셈이죠. 성능이 가짜로 아주 좋게 나오고, 실전에 배포하면 무너집니다. 14강에서 말한 데이터 누수의 가장 전형적인 형태입니다.

2. 평가 지표

import numpy as np 기록 = {} # 모델 이름 → 점수. 같은 이름을 다시 평가하면 덮어쓴다 def 평가(이름, 예측): 실제 = 검증.values 예측 = np.asarray(예측, dtype=float) mae = np.mean(np.abs(실제 - 예측)) rmse = np.sqrt(np.mean((실제 - 예측) ** 2)) mape = np.mean(np.abs((실제 - 예측) / 실제)) * 100 기록[이름] = {"MAE": round(mae), "RMSE": round(rmse), "MAPE(%)": round(mape, 1)} return mape print("평가 함수 준비 완료 — 점수는 기록에 쌓입니다")
세 가지 오차 지표
MAE  =  평균( |실제 − 예측| )
RMSE  =  √평균( (실제 − 예측)2 )
MAPE  =  평균( |실제 − 예측| / 실제 ) × 100%
  • MAE평균 절대 오차. "평균 8만원쯤 틀린다" — 가장 해석하기 쉽습니다
  • RMSE제곱하므로 큰 실수에 더 큰 벌점. 크게 틀리면 안 되는 상황(재고, 인력)에서 씁니다
  • MAPE비율이라 단위가 없어 서로 다른 데이터를 비교할 수 있습니다. 단 실제값이 0에 가까우면 폭발합니다
어느 지표를 볼까
  • 보고할 땐 MAE — "평균 8만원 틀립니다"가 가장 잘 통합니다.
  • 모델을 고를 땐 RMSE 또는 MAPE — 큰 실수를 피하고 싶으면 RMSE.
  • 여러 지표가 다른 모델을 가리키면 그 자체가 정보입니다 — "A는 평소에 정확한데 가끔 크게 틀리고, B는 고르게 조금씩 틀린다"는 뜻이죠.

3. 기준선부터 만들기

이 강의에서 가장 중요한 부분입니다. 복잡한 모델을 만들기 전에 바보 같은 방법들을 먼저 돌려보세요. 이걸 못 이기면 복잡한 모델은 아무 의미가 없습니다.

결과 = {} # ① 마지막 값을 그대로 (나이브) 결과["① 마지막값"] = 평가("① 마지막값 그대로", np.repeat(학습.iloc[-1], H)) # ② 최근 28일 평균 결과["② 최근28일 평균"] = 평가("② 최근 28일 평균", np.repeat(학습.iloc[-28:].mean(), H)) # ③ 지난주 같은 요일 (계절성 나이브) 결과["③ 지난주 같은요일"] = 평가("③ 지난주 같은 요일", 학습.iloc[-7:].values.tolist() * 4) pd.DataFrame(기록).T # 마지막 줄에 값만 두면 표로 보여준다
왜 기준선이 필수인가 · "우리 모델의 MAPE가 10%입니다"라는 말은 그 자체로는 아무 의미가 없습니다. "단순 평균이 9.8%인데 우리 모델은 10.7%입니다"라고 해야 비로소 판단할 수 있죠. 기준선 없는 성능 보고는 보고가 아닙니다.

4. 지수평활과 SARIMA

from statsmodels.tsa.holtwinters import ExponentialSmoothing 모델 = ExponentialSmoothing( 학습, trend="add", # 추세 있음 damped_trend=True, # 추세를 무한정 연장하지 않음 seasonal="add", # 계절성 있음 seasonal_periods=7, # 주기 7일 ).fit() 결과["④ 홀트윈터스"] = 평가("④ 홀트윈터스(주간)", 모델.forecast(H).values) pd.DataFrame(기록).T
damped_trend=True 를 거의 항상 켜세요 끄면 학습 구간의 추세를 그대로 무한정 연장합니다. 2년간 우상향한 데이터라면 10년 뒤 매출이 천문학적으로 나오죠. 감쇠(damped)를 켜면 추세가 점점 완만해져 현실적인 예측이 됩니다. 실제로 이 옵션 없이 돌리면 MAPE가 42%까지 치솟습니다.
from statsmodels.tsa.arima.model import ARIMA 사리마 = ARIMA( 학습, order=(1, 1, 1), # (p, d, q) — 비계절 부분 seasonal_order=(1, 1, 1, 7), # (P, D, Q, s) — 계절 부분, 주기 7 ).fit() 결과["⑤ SARIMA"] = 평가("⑤ SARIMA(1,1,1)(1,1,1,7)", 사리마.forecast(H).values) pd.DataFrame(기록).T
SARIMA 파라미터 읽는 법
ARIMA( p, d, q ) × ( P, D, Q )s
  • p자기회귀 — 과거 몇 개 값을 볼 것인가
  • d차분 — 몇 번 빼서 추세를 없앨 것인가 (14강의 diff)
  • q이동평균 — 과거 오차 몇 개를 반영할 것인가
  • 대문자같은 것을 계절 주기로. D=1 은 diff(7)
  • s주기. 일별-주간이면 7, 월별-연간이면 12
파라미터를 어떻게 고르나
정석은 ACF/PACF 그림을 보는 것이지만, 실무에서는 여러 조합을 돌려보고 검증 성능이 가장 좋은 걸 고릅니다. (1,1,1)(1,1,1,7) 은 무난한 출발점입니다. 자동으로 찾아주는 pmdarima.auto_arima 도 있습니다.

5. 결과 — 단순한 게 이겼습니다

print("MAPE 낮은 순\n") for 이름, 값 in sorted(결과.items(), key=lambda x: x[1]): 막대 = "█" * int(값 * 2) print(f" {값:5.1f}% {막대} {이름}")
최근 28일 평균(9.8%)이 SARIMA(10.7%)와 홀트윈터스(11.7%)를 이겼습니다

이건 실수가 아니라 흔히 일어나는 일입니다. 이유는 이렇습니다.

  • 28일 평균에는 요일 효과가 이미 녹아 있습니다. 4주치를 평균 내면 각 요일이 4번씩 들어가니까요.
  • 복잡한 모델은 추정할 파라미터가 많아 학습 데이터의 노이즈까지 배웁니다(과적합).
  • 28일이라는 짧은 예측 구간에서는 정교한 모델의 이점이 크지 않습니다.

교훈: 복잡한 모델을 쓰기로 결정하려면 기준선을 실제로 이겨야 합니다. "SARIMA를 썼습니다"가 아니라 "SARIMA가 단순 평균보다 나았습니다"를 보여주세요. 못 이겼다면 단순한 걸 쓰는 게 맞습니다 — 빠르고, 설명하기 쉽고, 덜 망가집니다.

6. 예측구간 — 점이 아니라 범위로

"다음 주 토요일 매출 115만원"이라는 점 예측은 반드시 틀립니다. 정직한 예측은 범위로 말합니다.

예보 = 사리마.get_forecast(H) 구간 = 예보.conf_int() 표 = pd.DataFrame({ "예측": 예보.predicted_mean.values / 10000, "하한": 구간.iloc[:, 0].values / 10000, "상한": 구간.iloc[:, 1].values / 10000, "실제": 검증.values / 10000, }, index=검증.index).round(1) print(표.head(7).to_string()) 포함 = ((표["실제"] >= 표["하한"]) & (표["실제"] <= 표["상한"])).sum() print(f"\n95% 구간이 실제를 포함: {포함}/{H}일 ({포함/H*100:.0f}%)")

구간의 폭을 보세요 · 예측이 87만원인데 구간이 40만~133만원입니다. 3배 넘게 벌어지죠. "이게 무슨 예측이냐" 싶겠지만, 이게 정직한 예측입니다.

실제로 28일 전부가 구간 안에 들어왔습니다(28/28). 좁은 구간을 자랑하는 예측보다, 넓지만 실제로 맞는 구간이 쓸모 있습니다. (모듈 05에서 신뢰수준과 폭의 맞바꿈을 슬라이더로 볼 수 있습니다.)

7. 실무 체크리스트

예측 프로젝트를 시작할 때
  1. 예측 기간을 먼저 정하세요. 1주 뒤와 1년 뒤는 완전히 다른 문제입니다.
  2. 기준선을 먼저 만드세요. 마지막값·평균·작년같은날. 이걸 못 이기면 끝입니다.
  3. 시간 순서대로 자르세요. 무작위 분리는 반칙.
  4. 여러 시점에서 검증하세요. 한 번의 28일로 판단하면 운일 수 있습니다 (아래 참고).
  5. 예측구간을 함께 내세요. 점 예측만 주면 받는 사람이 오해합니다.
  6. 주기적으로 다시 학습하세요. 세상은 변합니다.
# 한 번의 검증은 운일 수 있다. 시점을 옮겨가며 여러 번 평가한다. 점수 = [] for 끝 in [28, 56, 84, 112, 140]: tr = s[:-끝] te = s[-끝:-끝+H] if 끝 > H else s[-끝:] if len(te) < H: continue 예측 = np.repeat(tr.iloc[-28:].mean(), len(te)) mape = np.mean(np.abs((te.values - 예측) / te.values)) * 100 점수.append(mape) print(f" {te.index[0].date()} 부터 {len(te)}일 MAPE {mape:5.1f}%") print(f"\n평균 MAPE {np.mean(점수):.1f}% 표준편차 {np.std(점수):.1f}%p")
충격적인 결과 — 우리가 본 9.8%는 운이 좋았던 겁니다

똑같은 방법(최근 28일 평균)인데 시점만 옮기니 MAPE가 이렇게 나옵니다.

9.8%가 아니라 17.5% ± 4.9%p 라고 보고해야 정직합니다. 운 좋은 구간 하나를 골라 "우리 모델은 오차 10%"라고 말하는 것은 6강에서 배운 p-해킹과 같은 종류의 자기기만입니다. 의도가 없어도 결과적으로 그렇게 됩니다 — 그래서 검증 시점을 미리 정해두는 게 중요합니다.

그럼 §5의 순위표는 무의미한가요?
아닙니다. 같은 조건에서 여러 방법을 비교한 것이라 상대적 순위는 여전히 정보입니다. 다만 절대적인 성능 수치("우리는 9.8%")로 쓰면 안 됩니다. 제대로 하려면 모든 방법을 모든 시점에서 돌려 평균 순위를 봐야 합니다. 연습 문제로 직접 해보세요.
# 문제 1. 예측 기간 H 를 7일로 바꿔서 다시 비교해보세요. # 짧은 예측에서는 어떤 방법이 이기나요? # 문제 2. 방문객(visitors)을 예측해보세요. 매출보다 쉬운가요, 어려운가요? # 문제 3. SARIMA 의 order 를 (2,1,2) 로 바꿔보세요. 나아지나요?
모범 답안 보기
def 실험(시리즈, H): tr, te = 시리즈[:-H], 시리즈[-H:] def m(p): p = np.asarray(p, dtype=float) return np.mean(np.abs((te.values - p) / te.values)) * 100 out = { "마지막값": m(np.repeat(tr.iloc[-1], H)), "최근28일 평균": m(np.repeat(tr.iloc[-28:].mean(), H)), "지난주 요일": m((tr.iloc[-7:].values.tolist() * (H // 7 + 1))[:H]), } try: a = ARIMA(tr, order=(1,1,1), seasonal_order=(1,1,1,7)).fit() out["SARIMA"] = m(a.forecast(H).values) except Exception as e: out["SARIMA"] = float("nan") return out # 문제 1 print("[매출 · 7일 예측]") for k, v in sorted(실험(s, 7).items(), key=lambda x: x[1]): print(f" {v:5.1f}% {k}") # 문제 2 v_series = df.set_index("date").asfreq("D")["visitors"].interpolate() print("\n[방문객 · 28일 예측]") for k, val in sorted(실험(v_series, 28).items(), key=lambda x: x[1]): print(f" {val:5.1f}% {k}") # 문제 3 print("\n[SARIMA order 비교 · 28일]") for order in [(1,1,1), (2,1,2), (0,1,1)]: try: a = ARIMA(학습, order=order, seasonal_order=(1,1,1,7)).fit() p = a.forecast(H).values mape = np.mean(np.abs((검증.values - p) / 검증.values)) * 100 print(f" order={order} MAPE {mape:.1f}%") except Exception as e: print(f" order={order} 실패: {type(e).__name__}")

문제 1의 결과가 순위를 완전히 뒤집습니다. 7일 예측에서는 SARIMA가 7.6%로 1등이고 최근 28일 평균은 14.2%로 3등이 됩니다. 28일 예측에서와 정반대죠.

이유는 명확합니다. 7일 안에서는 요일 패턴이 결정적인데, 평균값 하나로는 요일 변동을 전혀 따라갈 수 없습니다. 반면 28일이면 요일이 네 번씩 돌아 평균이 유리해집니다.

"어떤 모델이 좋은가"에 절대적인 답은 없습니다. 예측 기간이 바뀌면 답도 바뀝니다. 그래서 §7의 1번이 "예측 기간을 먼저 정하라"인 것입니다. 문제 3에서 order 를 바꿔도 10.7~10.8%로 거의 차이가 없는 것과 대조적이죠 — 파라미터 미세조정보다 문제 설정이 훨씬 중요합니다.

16강 요약

  • 시간 순서대로 학습/검증을 나눈다. 무작위 분리는 반칙.
  • MAE(해석 쉬움) · RMSE(큰 실수에 벌점) · MAPE(비교 가능, 0 근처에서 폭발).
  • 기준선을 먼저 만든다. 마지막값 · 최근 평균 · 작년 같은 날.
  • 이 데이터에서는 "최근 28일 평균"(9.8%)이 SARIMA(10.7%)를 이겼다. 복잡한 모델은 기준선을 실제로 이겨야 쓸 이유가 생긴다.
  • 지수평활에는 damped_trend=True 를 켤 것 (없으면 MAPE 42%).
  • 예측구간을 함께 낸다. 넓어도 실제로 맞는 구간이 쓸모 있다(28/28 포함).
  • 여러 시점에서 검증하고 평균과 편차를 함께 보고한다.
