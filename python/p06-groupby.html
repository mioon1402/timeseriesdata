1. groupby의 원리

groupby 는 세 단계로 동작합니다. 영어로 Split – Apply – Combine 이라고 부릅니다.

groupby 의 3단계
① 쪼갠다 (Split) — 요일이 같은 행끼리 7덩어리로
② 계산한다 (Apply) — 덩어리마다 평균을 낸다
③ 합친다 (Combine) — 결과 7개를 표 하나로
  • 코드df.groupby("쪼갤기준")["계산할열"].평균함수()
import pandas as pd df = pd.read_csv("cafe_sales.csv", parse_dates=["date"]) print(df.groupby("weekday")["visitors"].mean().round(1).to_string())

숫자가 나왔는데 순서가 이상합니다. 금 → 목 → 수 → 월 → 일 → 토 → 화. 요일 순서가 아니라 가나다순입니다.

2. 순서 문제

pandas는 요일이 무엇인지 모릅니다. 그냥 문자열이니 사전 순으로 정렬한 거죠. 해결법은 두 가지입니다.

순서 = ["월", "화", "수", "목", "금", "토", "일"] # 방법 1: reindex 로 원하는 순서를 강제한다 (간단) 결과 = df.groupby("weekday")["visitors"].mean().reindex(순서) print(결과.round(1).to_string())
# 열 자체에 '순서'를 알려주면 이후 모든 작업에서 유지된다 df["weekday"] = pd.Categorical(df["weekday"], categories=순서, ordered=True) print(df.groupby("weekday", observed=True)["visitors"].mean().round(1).to_string()) print() print("정렬도 요일 순으로:", df.sort_values("weekday")["weekday"].head(3).tolist())
어느 쪽을 쓸까
  • 한 번만 쓸 거면 reindex — 간단합니다.
  • 계속 쓸 거면 pd.Categorical — 그래프 축, 정렬, 다른 집계까지 전부 순서가 유지됩니다. 9강에서 그래프를 그릴 때 진가가 드러납니다.

observed=True 는 "실제로 데이터에 있는 범주만 보여줘"라는 뜻입니다. 안 쓰면 빈 범주까지 나올 수 있습니다.

3. 여러 통계를 한 번에 — agg

평균만 보면 부족합니다. 5강에서 배웠듯 퍼짐과 개수를 함께 봐야 합니다.

요약 = df.groupby("weekday", observed=True).agg( 일수 = ("visitors", "size"), 평균방문 = ("visitors", "mean"), 표준편차 = ("visitors", "std"), 중앙값 = ("visitors", "median"), 평균매출 = ("sales", "mean"), ).round(1) print(요약.to_string())

이 표 하나로 많은 게 보입니다.

  • 토요일이 227명으로 최고, 월요일이 144명으로 최저 — 1.57배 차이
  • 토요일은 표준편차도 67.2로 가장 큽니다. 잘 되는 날과 안 되는 날의 편차가 크다는 뜻
  • 일수가 요일마다 104~105일로 고르게 분포 — 특정 요일이 과대표집되지 않았습니다
agg 문법 두 가지
  • 이름 붙이기 (권장) — 평균방문=("visitors", "mean")
    결과 열 이름을 내가 정할 수 있어 읽기 좋습니다.
  • 목록으로 — .agg(["mean", "std"])
    빠르지만 열 이름이 2층으로 쌓여 다루기 번거롭습니다.

4. 두 개 이상의 기준으로 쪼개기

df["주말"] = df["date"].dt.dayofweek >= 5 결과 = df.groupby(["주말", "is_holiday"])["visitors"].agg(["size", "mean"]).round(1) print(결과.to_string())

네 조합이 나옵니다. 재미있는 건 평일 공휴일(195.2명)이 그냥 주말(203.1명)에 육박한다는 점입니다. "쉬는 날"이라는 성격이 요일보다 중요할 수 있다는 신호죠.

단, 공휴일 표본은 30일과 5일뿐입니다 평일 공휴일 30일, 주말 공휴일 단 5일. 5일의 평균으로 "주말 공휴일이 211명"이라고 말하는 건 위험합니다. 표본이 작으면 평균이 크게 흔들리니까요(모듈 04의 σ/√n). 그룹 크기를 항상 함께 출력하는 이유가 이것입니다.

5. pivot_table — 표로 보기

그룹이 두 개일 때 groupby 결과는 세로로 길게 나옵니다. 가로세로 표로 보고 싶으면 pivot_table 을 씁니다. 엑셀의 피벗테이블과 같습니다.

df["연"] = df["date"].dt.year df["월"] = df["date"].dt.month 표 = df.pivot_table(values="sales", index="월", columns="연", aggfunc="mean") print("월별 평균 매출 (만원)") print((표 / 10000).round(1).to_string())

한눈에 두 가지가 보입니다.

  • 계절성 — 세로로 읽으면 겨울(1월)이 낮고 여름(7·8월)이 높습니다.
  • 성장 — 가로로 읽으면 2025년이 2024년보다 모든 달에서 높습니다.

이 두 가지를 분리해내는 게 15강(추세와 계절성 분해)의 주제입니다.

표 = df.pivot_table(values="sales", index="월", columns="연", aggfunc="mean") 표["성장률"] = (표[2025] / 표[2024] - 1) * 100 print((표[["성장률"]]).round(1).to_string()) print() print(f"연간 평균 성장률: {표['성장률'].mean():.1f}%")

6. 그룹 크기를 꼭 함께 보세요

비교 = df.groupby("is_holiday").agg( 일수 = ("visitors", "size"), 평균 = ("visitors", "mean"), 표준편차 = ("visitors", "std"), ) # 표준오차 = 표준편차 / √n (모듈 04) 비교["표준오차"] = 비교["표준편차"] / (비교["일수"] ** 0.5) print(비교.round(1).to_string())

공휴일 그룹은 35일뿐이라 표준오차가 훨씬 큽니다. "공휴일 평균 197.5명"이라는 숫자에 붙어 있는 불확실성이 "평일 평균 175.5명"보다 크다는 뜻이죠. 이 불확실성을 구간으로 표현하는 게 13강(신뢰구간)입니다.

규칙 · 그룹별 평균을 보고할 때는 항상 size 를 함께 넣으세요. agg 에 한 줄 더 쓰는 것뿐인데, 잘못된 결론을 막아줍니다.

7. 실전: 쪼개면 방향이 바뀔 수도 있습니다

전체로 보면 A가 좋은데 그룹별로 보면 B가 좋은 — 심슨의 역설이 실제로 일어날 수 있습니다 (모듈 08에서 슬라이더로 직접 만들어볼 수 있습니다).

우리 데이터로 비슷한 상황을 만들어봅시다. "비 오는 날은 손님이 적다"를 2강에서 확인했는데, 계절을 나눠서 보면 어떨까요?

def 계절(m): if m in (3, 4, 5): return "봄" if m in (6, 7, 8): return "여름" if m in (9, 10, 11): return "가을" return "겨울" df["계절"] = df["월"].map(계절) df["비"] = df["rain_mm"] > 0 # 전체로 볼 때 전체 = df.groupby("비")["visitors"].mean() print(f"[전체] 비 안옴 {전체[False]:.1f}명 / 비 옴 {전체[True]:.1f}명 " f"→ 차이 {전체[True] - 전체[False]:+.1f}") # 계절별로 나눠서 볼 때 print("\n[계절별]") 표 = df.pivot_table(values="visitors", index="계절", columns="비", aggfunc="mean") 표["차이"] = 표[True] - 표[False] print(표.round(1).reindex(["봄", "여름", "가을", "겨울"]).to_string())

계절별로 봐도 모든 계절에서 비 오는 날이 적습니다. 방향이 뒤집히지는 않았지만, 차이의 크기는 계절마다 다릅니다. 전체 숫자 하나로는 이걸 알 수 없었죠.

이게 "통제(control)"의 기본입니다
  • 계절을 고정한 채로 비의 효과를 보면, 계절이 끼어드는 영향을 제거할 수 있습니다.
  • 여기서는 방향이 그대로였으니 "비가 정말 영향을 준다"는 근거가 강해진 것입니다.
  • 만약 방향이 뒤집혔다면? 전체 결론이 계절 때문에 생긴 착시였다는 뜻입니다.
  • 단, 아무 변수나 통제하면 안 됩니다. 무엇을 통제해야 하는지는 모듈 08 §4에서 다룹니다 (교란은 통제, 매개는 금지, 충돌은 절대 금지).
# 문제 1. 계절별 평균 매출과 일수를 함께 구해보세요. # 문제 2. 요일별 '객단가'(매출 ÷ 방문객)를 구해보세요. # 어느 요일이 가장 높은가요? # 문제 3. 연도별·계절별 평균 매출을 pivot_table 로 만들어보세요.
모범 답안 보기
계절순 = ["봄", "여름", "가을", "겨울"] # 문제 1 print(df.groupby("계절").agg(일수=("sales", "size"), 평균매출=("sales", "mean")) .reindex(계절순).round(0).to_string()) # 문제 2 — 주의: 각 날의 객단가를 먼저 구한 뒤 평균내야 한다 영업 = df[df["visitors"] > 0].copy() 영업["객단가"] = 영업["sales"] / 영업["visitors"] print() print(영업.groupby("weekday", observed=True)["객단가"].mean().round(0).to_string()) # 문제 3 print() print((df.pivot_table(values="sales", index="계절", columns="연", aggfunc="mean") .reindex(계절순) / 10000).round(1).to_string())

문제 2의 결과가 이 강의에서 가장 중요합니다. 객단가가 요일별로 4,941원 ~ 4,958원 으로 거의 차이가 없습니다. 방문객은 월요일 144명, 토요일 227명으로 1.57배나 차이 나는데 말이죠.

즉 "토요일 매출이 높은 건 손님이 많아서지, 한 명이 더 많이 써서가 아닙니다." 매출을 쪼개서 봤기 때문에 알 수 있는 사실입니다. 실무에서 이런 결론은 곧바로 행동으로 이어집니다 — 객단가를 올리는 정책(세트 메뉴, 업셀)과 손님을 늘리는 정책(홍보, 영업시간)은 완전히 다른 일이니까요.

참고로 문제 2에는 함정도 있습니다. "매출 합계 ÷ 방문객 합계"(4,932원)와 "각 날의 객단가를 평균"(4,952원)은 다른 값입니다. 전자는 가중평균(손님이 많은 날에 더 큰 비중), 후자는 단순평균(모든 날이 동등)이죠. "손님 한 명이 평균 얼마 쓰나"는 전자, "하루 평균 객단가"는 후자입니다.

6강 요약

  • groupby = 쪼개고(Split) → 계산하고(Apply) → 합치기(Combine).
  • 문자열 그룹은 가나다순으로 정렬된다. reindex 나 pd.Categorical 로 순서 지정.
  • agg(이름=("열","함수")) 형식으로 여러 통계를 이름 붙여 한 번에.
  • pivot_table 은 두 기준을 가로세로 표로. 계절성과 성장을 동시에 볼 수 있다.
  • 그룹 크기(size)를 항상 함께 출력할 것. 표본이 작으면 평균이 흔들린다.
  • 변수를 고정한 채 비교하는 것이 통제의 기본. 단, 통제할 변수는 신중히 고를 것.
