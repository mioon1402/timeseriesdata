관계를 숫자로

11강에서 산점도로 눈으로 본 관계를 이제 숫자로 확정합니다. 상관계수 하나, 회귀 계수 하나. 그리고 그보다 훨씬 중요한 것 — 그 숫자를 어디까지 믿어도 되는가.

1. 상관계수

import pandas as pd from scipy import stats df = pd.read_csv("cafe_sales.csv", parse_dates=["date"]) d = df.dropna(subset=["avg_temp", "sales"]) 피어슨 = d["avg_temp"].corr(d["sales"]) 스피어만 = d["avg_temp"].corr(d["sales"], method="spearman") print(f"피어슨 r = {피어슨:.4f} (직선 관계의 강도)") print(f"스피어만 ρ = {스피어만:.4f} (순위 관계의 강도)") print() r, p = stats.pearsonr(d["avg_temp"], d["sales"]) print(f"scipy: r={r:.4f}, p={p:.3g}") print(f"결정계수 r² = {r**2:.4f} → 매출 변동의 {r**2*100:.1f}%를 기온으로 설명")

이건 관계가 완전한 직선은 아니라는 신호입니다. 순위로 보면 더 뚜렷하게 함께 움직인다는 뜻이죠. 실제로 7강에서 기온대별로 묶어봤을 때 144 → 155 → 190 → 197 → 242명으로 계단식이었지 일정한 간격이 아니었습니다. 두 계수가 크게 다르면 산점도를 다시 보세요.
p값이 7.24e-43 이라고 관계가 강한 게 아닙니다 p값이 극도로 작은 건 "r이 0은 아니다"를 아주 확신한다는 뜻일 뿐입니다. 관계의 강도는 r(0.48)과 r²(0.23)이 말합니다. 매출 변동의 77%는 기온으로 설명되지 않습니다. n이 727이나 되니 아무리 약한 관계도 "유의"하게 나옵니다 (모듈 06 실험 B).

2. 회귀 — 관계를 식으로

상관계수는 "얼마나 함께 움직이나"만 말합니다. "기온이 1도 오르면 매출이 얼마 오르나"에 답하려면 회귀가 필요합니다.

결과 = stats.linregress(d["avg_temp"], d["sales"]) print(f"기울기: {결과.slope:>12,.0f} 원/℃") print(f"절편: {결과.intercept:>12,.0f} 원") print(f"r: {결과.rvalue:>12.4f}") print(f"r²: {결과.rvalue**2:>12.4f}") print(f"p: {결과.pvalue:>12.3g}") print() print(f"식: 매출 = {결과.intercept:,.0f} + {결과.slope:,.0f} × 기온")
단순선형회귀
ŷ  =  a  +  b·x
매출 = 722,344 + 12,008 × 기온
  • b (기울기)x가 1 늘 때 y가 평균적으로 얼마나 변하는가. 여기서는 기온 1℃당 매출 12,008원
  • a (절편)x=0일 때의 예측값. 기온 0℃일 때 72만원 — 다만 해석에 주의(§6)
  • ŷ예측값. 실제값 y와 다릅니다. 그 차이가 잔차

3. statsmodels 결과표 읽는 법

실무에서는 statsmodels 를 씁니다. 계수의 불확실성까지 함께 나오기 때문입니다.

import statsmodels.api as sm X = sm.add_constant(d["avg_temp"]) # 절편을 위한 상수항 추가 모델 = sm.OLS(d["sales"], X).fit() print(모델.summary().tables[1]) print() print(f"R² = {모델.rsquared:.4f} 관측수 = {int(모델.nobs)}")

4. 잔차 진단 — 모델을 믿기 전에

회귀식이 나왔다고 끝이 아닙니다. 잔차(실제 − 예측)에 패턴이 남아 있으면 모델이 뭔가를 놓친 것입니다.

5. 다중회귀 — 변수를 여러 개

기온만으로는 매출 변동의 23%밖에 설명하지 못했습니다. 비와 주말도 함께 넣어봅시다.

d2 = d.copy() d2["주말"] = (d2["date"].dt.dayofweek >= 5).astype(int) X2 = sm.add_constant(d2[["avg_temp", "rain_mm", "주말"]]) 모델2 = sm.OLS(d2["sales"], X2).fit() print(모델2.summary().tables[1]) print() print(f"R² {모델2.rsquared:.4f} (기온만: 0.2315)") print(f"수정 R² {모델2.rsquared_adj:.4f}")

설명력이 23% → 39% 로 올랐습니다. 계수도 해석해봅시다.

  • 기온 +12,410원/℃ — 다른 조건이 같을 때
  • 강수량 −7,626원/mm — 비가 10mm 오면 7.6만원 감소
  • 주말 +172,900원 — 주말이면 평일보다 17만원 더
"다른 조건이 같을 때"가 핵심입니다

다중회귀의 계수는 나머지 변수를 고정한 채의 효과입니다. 기온 계수가 단순회귀의 12,008에서 12,410으로 바뀐 것을 보세요. 비와 주말을 통제하자 기온의 순수 효과가 조금 더 크게 드러난 겁니다.

이게 6강·모듈 08에서 배운 통제(control)를 회귀로 하는 방법입니다. 다만 아무 변수나 넣으면 안 됩니다 — 교란은 넣고, 매개는 빼고, 충돌은 절대 넣지 마세요(모듈 08 §4).

R²는 변수를 넣을수록 무조건 올라갑니다 난수 열을 넣어도 R²는 아주 조금이나마 올라갑니다. 그래서 모델을 비교할 땐 수정 R²(변수 개수에 벌점)를 보거나, 더 좋게는 새 데이터에서의 성능을 봐야 합니다(16강).

방문객(visitors)을 설명변수로 넣으면 R²가 0.99가 됩니다. 대단해 보이지만 아무 쓸모 없습니다 — 매출 = 방문객 × 객단가라 같은 것을 양쪽에 넣은 것이니까요.

6. 계수를 말로 옮기기

✗ 인과 주장 "기온을 1도 올리면 매출이 12,410원 증가한다"
→ 관측 데이터로는 이렇게 말할 수 없습니다. 기온은 우리가 조작한 게 아닙니다.
✓ 연관 진술 "비와 요일이 같을 때, 기온이 1℃ 높은 날은 매출이 평균 12,410원 높았다 (95% CI: 11,000~13,900원, n=722)"
절편 해석에 주의

절편 688,200원은 "기온 0℃, 비 0mm, 평일"일 때의 예측값입니다. 기온 0도는 실제로 데이터에 있으니 그나마 해석 가능하지만, x=0이 현실에 없는 값이면 절편은 의미가 없습니다.

예: 키로 몸무게를 예측하는 회귀에서 절편은 "키 0cm인 사람의 몸무게"입니다. 이럴 땐 중심화(각 값에서 평균을 빼기)를 하면 절편이 "평균적인 사람"의 값이 되어 해석이 살아납니다.

import pandas as pd 새로운날 = pd.DataFrame({ "const": [1, 1, 1], "avg_temp": [5, 20, 30], "rain_mm": [0, 0, 20], "주말": [0, 1, 1], }) 예측값 = 모델2.predict(새로운날) for i, row in 새로운날.iterrows(): 상황 = f"기온 {row['avg_temp']:.0f}℃, 비 {row['rain_mm']:.0f}mm, {'주말' if row['주말'] else '평일'}" print(f"{상황:32s} → {예측값[i]:,.0f}원")
관측 범위 밖은 예측하지 마세요 우리 데이터의 기온은 −7.3℃ ~ 32.2℃ 입니다. 기온 45℃일 때의 매출을 이 식으로 계산하면 안 됩니다. 그 구간에서도 관계가 직선이라는 증거를 본 적이 없기 때문입니다. 실제로는 너무 더우면 아예 외출을 안 할 수도 있죠.
# 문제 1. 방문객(visitors)을 기온·강수량·주말로 회귀해보세요. # R²가 매출 모델과 어떻게 다른가요? # 문제 2. 이상치(방문객 300명 이상인 날)를 빼고 12-5 모델을 다시 돌려보세요. # 계수가 얼마나 바뀌나요? # 문제 3. 강수량 대신 '비가 왔는가(0/1)'를 넣으면 계수가 어떻게 해석되나요?
모범 답안 보기
# 문제 1 m_v = sm.OLS(d2["visitors"], X2).fit() print("방문객 모델 R²:", round(m_v.rsquared, 4)) print(m_v.summary().tables[1]) # 문제 2 평상시 = d2[d2["visitors"] < 300] X3 = sm.add_constant(평상시[["avg_temp", "rain_mm", "주말"]]) m3 = sm.OLS(평상시["sales"], X3).fit() print("\n[이상치 제외]") print(m3.summary().tables[1]) print("R²:", round(m3.rsquared, 4), " (제외 전 0.3852)") # 문제 3 d2["비옴"] = (d2["rain_mm"] > 0).astype(int) X4 = sm.add_constant(d2[["avg_temp", "비옴", "주말"]]) m4 = sm.OLS(d2["sales"], X4).fit() print("\n[비를 0/1 로]") print(m4.summary().tables[1])

문제 2가 중요합니다. 이상치 하나를 빼면 R²가 크게 올라갑니다. 모델이 좋아진 게 아니라 설명하기 어려운 점을 치운 것뿐입니다. "이상치를 빼니 모델이 좋아졌다"는 발견이 아니라 정의상 당연한 일입니다. 뺐다면 반드시 밝히세요.

문제 3에서 비옴 계수는 "비가 온 날은 안 온 날보다 평균 얼마 낮은가"입니다. 강수량(mm)을 쓸 때의 "1mm당" 해석과 완전히 다릅니다. 0/1 변수의 계수는 "그룹 간 차이"로 읽으세요.

12강 요약

  • 피어슨=직선 관계, 스피어만=순위 관계. 둘이 다르면 산점도를 다시 볼 것.
  • 작은 p값은 강한 관계가 아니라 "0은 아니다"라는 확신일 뿐. 강도는 r².
  • 회귀식 ŷ = a + b·x — b는 "x가 1 늘 때 y의 평균 변화".
  • 결과표에서 신뢰구간을 가장 먼저 보라.
  • 잔차에 패턴이 남으면 모델이 뭔가를 놓친 것. 곡선·깔때기·영향점 확인.
  • 다중회귀 계수는 "다른 조건이 같을 때". 넣을 변수는 신중히 고를 것.
  • R²는 변수를 넣으면 무조건 오른다. 수정 R²나 새 데이터 성능으로 비교.
  • 계수는 연관이지 인과가 아니다. 관측 범위 밖은 예측하지 말 것.
