1. 열 꺼내기

먼저 데이터를 다시 불러옵니다. 그리고 열 하나를 꺼내볼 텐데, 대괄호를 한 겹 쓰느냐 두 겹 쓰느냐에 따라 결과의 종류가 달라집니다.

import pandas as pd df = pd.read_csv("cafe_sales.csv") 한겹 = df["sales"] # Series (1차원) 두겹 = df[["date", "weekday", "sales"]] # DataFrame (2차원 표) print("한 겹:", type(한겹).__name__) print("두 겹:", type(두겹).__name__) print() print(한겹.head(3))
Series (한 겹)DataFrame (두 겹)
모양값이 한 줄로 늘어선 것행과 열이 있는 표
쓰는 법df["sales"]df[["sales"]]
계산.mean() → 숫자 하나.mean() → 열별 결과
언제한 열만 계산할 때여러 열을 함께 보거나 저장할 때
기억할 것 안쪽 대괄호는 "목록"이라는 뜻입니다. df[["a", "b"]] 는 "a와 b라는 목록을 달라"는 말이고, 목록을 주면 표가 돌아옵니다. 그래서 열이 하나여도 표로 받고 싶으면 df[["sales"]] 처럼 씁니다.
df[["date", "weekday", "sales"]].head()

2. 조건으로 행 고르기

이제 핵심입니다. "방문객이 250명 이상이었던 날"만 보고 싶다고 합시다. 먼저 조건 자체가 무엇을 만드는지 봐야 이해가 됩니다.

조건 = df["visitors"] >= 250 print(조건.head()) print() print("전체 길이:", len(조건)) print("True 개수:", 조건.sum())

df["visitors"] >= 250 는 숫자를 돌려주는 게 아니라 행마다 True/False가 적힌 731칸짜리 목록을 만듭니다. 이걸 불리언 마스크(boolean mask)라고 부릅니다. 체에 비유하면 정확합니다 — True인 칸만 구멍이 뚫린 체를 만든 거죠.

이제 그 체를 데이터에 씌우면 통과한 행만 남습니다.

busy = df[df["visitors"] >= 250] print("250명 이상인 날:", len(busy), "일") busy[["date", "weekday", "visitors", "sales"]].head()

결과를 보면 토요일이 유난히 많습니다. 왼쪽 번호(인덱스)가 187, 208, 215…처럼 띄엄띄엄한 것도 눈여겨보세요. 원래 행 번호가 그대로 따라옵니다. 1강에서 본 731행 중 조건을 통과한 것만 남았다는 증거입니다.

3. 조건 여러 개 붙이기

"비 온 주말"처럼 조건이 둘 이상이면 기호로 잇습니다. 여기가 초보자가 가장 많이 틀리는 지점이니 천천히 봅시다.

조건 결합 기호
&  =  그리고 (AND)   ·   |  =  또는 (OR)   ·   ~  =  아닌 것 (NOT)
각 조건은 반드시 괄호로 감쌀 것
  • &파이썬의 and 가 아닙니다. pandas 에서는 and 를 쓰면 오류가 납니다
  • 괄호& 가 >= 보다 먼저 계산되기 때문에 필수입니다. 안 쓰면 엉뚱한 오류가 납니다
비온주말 = df[(df["weekday"].isin(["토", "일"])) & (df["rain_mm"] > 0)] print("비 온 주말:", len(비온주말), "일") print(비온주말[["date", "weekday", "rain_mm", "visitors"]].head(3)) # 또는(OR) — 무더위였거나 공휴일이었던 날 특별한날 = df[(df["avg_temp"] > 30) | (df["is_holiday"])] print() print("무더위 또는 공휴일:", len(특별한날), "일") # 아닌 것(NOT) — 공휴일이 아닌 날 print("공휴일이 아닌 날:", len(df[~df["is_holiday"]]), "일")
이 세 가지 실수가 전부입니다
잘못무슨 일이 일어나나고침
df[a and b] ValueError: The truth value of a Series is ambiguous & 를 쓰세요
df[df.a > 1 & df.b < 2] 괄호가 없어 1 & df.b 가 먼저 계산됨 → 이상한 오류 df[(df.a > 1) & (df.b < 2)]
df[df.a != None] 결측치가 안 걸러짐 df[df.a.notna()]

왜 and 가 안 되나? 파이썬의 and 는 값 하나가 참인지 거짓인지 묻는 말입니다. 그런데 우리가 넘긴 건 731개짜리 목록이죠. "731개가 참이냐"는 질문에 pandas 는 답할 수 없어서 "애매하다(ambiguous)"고 하는 겁니다. & 는 칸마다 하나씩 비교하는 기호라 목록에 쓸 수 있습니다.

4. 자주 쓰는 조건 도구

# isin — 목록 안에 있는가 봄 = df[df["date"].str[5:7].isin(["03", "04", "05"])] print("3~5월:", len(봄), "일") # between — 범위 안에 있는가 (양쪽 끝 포함) 쾌적 = df[df["avg_temp"].between(20, 25)] print("기온 20~25도:", len(쾌적), "일") # 문자열 다루기 — .str 을 붙이면 글자로 다룰 수 있다 print("2025년 데이터:", len(df[df["date"].str.startswith("2025")]), "일")

df["date"].str[5:7] 는 날짜 문자열 2024-01-01 의 6~7번째 글자, 즉 01(월)을 잘라낸 것입니다. 지금은 날짜가 문자열이라 이렇게 잘라 써야 하지만, 4강에서 진짜 날짜로 바꾸면 df["date"].dt.month == 3 처럼 훨씬 깔끔해집니다.

5. 정렬하기

# 매출 높은 순 print(df.sort_values("sales", ascending=False)[["date", "weekday", "sales"]].head(3)) # 두 기준으로 — 요일 순서대로, 각 요일 안에서는 매출 높은 순 print() print(df.sort_values(["weekday", "sales"], ascending=[True, False]) [["weekday", "date", "sales"]].head(3))
정렬 대신 쓰면 좋은 것 "상위 몇 개"만 필요하다면 nlargest / nsmallest 가 더 간결하고 빠릅니다.

6. loc과 iloc

지금까지는 df[조건] 으로 행만 골랐습니다. 행과 열을 동시에 지정하려면 loc 을 씁니다.

# df.loc[행조건, 열목록] df.loc[df["visitors"] > 300, ["date", "weekday", "visitors", "sales"]]
# 앞에서 3행, 앞에서 3열 df.iloc[:3, :3]
lociloc
기준이름(라벨)과 조건위치 번호 (0부터)
예df.loc[0, "sales"]df.iloc[0, 3]
범위 끝포함 — loc[0:2] 는 3개미포함 — iloc[0:2] 는 2개
언제대부분의 경우 (조건 필터링에 필수)"앞에서 n개"처럼 위치로 셀 때
범위 끝 규칙이 다릅니다 loc 은 끝을 포함하고 iloc 은 포함하지 않습니다. 파이썬의 일반 슬라이싱(iloc)에 익숙하다면 loc 이 예외처럼 느껴지는데, loc 은 "이름"으로 고르는 것이라 "그 이름까지"가 자연스럽기 때문입니다. 헷갈리면 결과 개수를 세어 확인하는 습관을 들이세요.

7. 실전: 비가 매출에 영향을 줄까?

배운 걸로 진짜 질문에 답해봅시다. "비 오는 날은 손님이 줄어드나?" — 필터링만 할 줄 알면 바로 확인됩니다.

비온날 = df[df["rain_mm"] > 0]["visitors"] 맑은날 = df[df["rain_mm"] == 0]["visitors"] print(f"비 온 날 {len(비온날):3d}일 평균 {비온날.mean():.1f}명") print(f"비 안 온 날 {len(맑은날):3d}일 평균 {맑은날.mean():.1f}명") print() print(f"차이 {맑은날.mean() - 비온날.mean():.1f}명 " f"({(비온날.mean() / 맑은날.mean() - 1) * 100:+.1f}%)")

비 온 날은 평균 163.5명, 안 온 날은 180.3명. 약 9% 적습니다. 그럴듯한 결과죠.

하지만 여기서 멈추면 안 됩니다

두 가지를 더 물어야 합니다.

  1. 이 차이가 우연일 수는 없나? 162일과 569일을 비교했는데, 똑같은 모집단에서 뽑아도 이 정도 차이는 그냥 나올 수 있습니다. 이걸 판단하는 게 가설검정입니다 — 모듈 06에서 카드를 섞어 직접 만들어볼 수 있고, 파이썬으로 계산하는 법은 13강에서 다룹니다.
  2. 진짜 원인이 비가 맞나? 여름에 비가 자주 오는데, 여름은 원래 손님이 많은 계절입니다. 계절을 무시하고 비만 보면 효과가 과소평가될 수 있습니다. 이런 교란변수 문제가 모듈 08(심슨의 역설)의 주제입니다.

필터링으로 얻은 숫자는 "질문의 시작"이지 "답"이 아닙니다. 이 감각이 데이터 분석가와 엑셀 사용자를 가릅니다.

# 문제 1. 주말(토·일) 중 매출이 가장 높았던 3일을 뽑아보세요. # 힌트: isin 으로 주말을 고르고 nlargest # 문제 2. 공휴일의 평균 방문객과, 공휴일이 아닌 날의 평균 방문객을 비교해보세요. # 힌트: df["is_holiday"] 는 이미 True/False 입니다 # 문제 3. 기온이 30도를 넘은 날은 며칠이고, 그날들의 평균 매출은 얼마인가요?
모범 답안 보기
# 문제 1 주말 = df[df["weekday"].isin(["토", "일"])] print(주말.nlargest(3, "sales")[["date", "weekday", "sales"]]) # 문제 2 공휴일 = df[df["is_holiday"]]["visitors"].mean() 평일 = df[~df["is_holiday"]]["visitors"].mean() print(f"\n공휴일 {공휴일:.1f}명 / 그 외 {평일:.1f}명 → {공휴일 - 평일:+.1f}명") # 문제 3 무더위 = df[df["avg_temp"] > 30] print(f"\n30도 초과: {len(무더위)}일, 평균 매출 {무더위['sales'].mean():,.0f}원")

문제 2의 답은 공휴일 197.5명 / 그 외 175.5명, 약 22명 많습니다. 그런데 공휴일은 20일 남짓밖에 안 됩니다. 표본이 적을수록 평균은 흔들립니다(모듈 04의 σ/√n). "22명 차이"를 곧이곧대로 믿기 전에 표본 수를 함께 보는 습관을 들이세요.

2강 요약

  • df["a"] 는 Series, df[["a","b"]] 는 DataFrame.
  • 조건식은 True/False 목록(마스크)을 만들고, df[마스크] 로 걸러낸다.
  • 조건 결합은 & | ~ — 각 조건을 괄호로 감쌀 것. and/or 는 쓸 수 없다.
  • isin(목록에 있나) · between(범위 안인가) · .str(문자열 다루기).
  • 정렬은 sort_values, 상위 몇 개만이면 nlargest.
  • loc 은 이름·조건으로(끝 포함), iloc 은 위치로(끝 미포함).
  • 필터링해서 나온 숫자는 답이 아니라 질문의 시작이다. 우연일 가능성과 교란변수를 항상 함께 생각할 것.
